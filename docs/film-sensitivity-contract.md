# 独立膜厚敏感性工作流

日期：2026-10-22。接口真值是 `coat_sim/core/film_sensitivity.py` 的独立 request/result 类型，普通厚度优化请求 v1 仍严格拒绝这些字段。

## 输入与能力边界

在膜系优化窗口选择“敏感性”，捕获当前完整设计、原波长/角度/偏振目标与来源版本。它不修改名义目标，不隐式增加余量，也不将任何固定扰动门槛混入名义验收。用户选择绝对 nm / 相对厚度误差、共模 / 逐层误差以及敏感性范数、有限场景最坏值或期望值目标。线性 Jacobian 估计与完整前向有限扰动分别报告，不能把一阶估计叫做蒙特卡洛制造良率或连续概率保证。

首版仅针对已有单面、前表面、支持解析导数的固定层序与 R/T 目标。材料 n/k、界面粗糙度、角度误差、相关随机场、相位/GD/GDD 与一般各向异性不在本版误差模型内。有限场景是明确列出的离散假设，不代表穷尽所有组合。原始网格不稀疏化。

## 唯一状态所有者、异步与取消

核心调用拥有冻结材料、请求、求解器与最佳完整候选。GUI 只拥有一次操作的代际、取消意图和队列观察者。调度器执行 `film_sensitivity` 独立作业；CLI 与 MCP 使用相同序列化合同。窗口关闭不将未完成结果自动应用到设计。重复开始在本次操作未终止前拒绝；编辑配置不会重标记正在执行的冻结请求。

取消在完整前向调用边界协作生效。预算耗尽、求解失败、收敛与用户取消分别报告；最佳完整候选不等于末次求解器点。检查点只保存已完整评分的候选及其冻结请求，载入时绑定完整设计、材料和目标，不依赖可伪造的展示 metadata。

## 结果、保存与应用

结果分别保留名义 max 违规 / 是否名义通过、用户选择的误差目标、线性估计与有限扰动评价。敏感性优化真实优化所选误差目标，允许名义指标变化，绝不把敏感性改善冒充名义通过。用户查看后显式应用；写回前复核来源版本与未提交编辑版本，来源变更则整次拒绝。失败/取消结果只能查看或保存，不自动回写。窗口沿用共享 Theme 控件和现有几何策略，无渲染后端降级。

## 实际首版接口与资源语义

FilmThicknessError(layer_id,magnitude,unit) 的 unit=absolute_nm 或 relative_fraction（0.01为1%）；GUI相对幅度以百分数显示并明确换算。独立场景为显式系数[-1,1]和正权重；GUI“生成±幅度场景”对独立模型只生成±单层组，不把它称为全部联合角点或蒙特卡洛。需要任意联合场景时使用独立JSON/CLI或MCP请求。

优化采用真实误差目标的确定性17点逐变量初扫和有界坐标模式搜索，不是旧名义优化器包装；局部step_tolerance、iteration_limit、evaluation_limit、physical_evaluation_failed和cancelled严格分开。GUI提供的200评价/20迭代仅为可见可清空初值，不是核心隐性限额。完整敏感性结果估计>256MiB明确拒绝并给出字节；分析缓存按32项和64MiB双限，不删场景或原采样点。

共享队列kind=film_sensitivity，独立job/checkpoint/result类型；MCP plan_film_sensitivity只读冻结、submit_film_sensitivity沿用已有计算确认/去重路径。首版GUI敏感性明确本地CPU队列，不继承普通优化器的远程/XPU选择，不宣称已支持敏感性远程设备。历史队列结果在只读独立报告窗口中打开，物理重放在后台完成；没有来源编辑上下文，不可应用。运行结果只在明确点击并确认应用后，沿现有applyOptimizedDesign版本/编辑epoch/撤销路径写回。

## 身份、终态与报告原子性门禁

提交只在client_request_id为None时派生默认身份；空字符串、bool或数值均不能静默变成另一个请求。历史报告先读取该job目录内不可变规范，匹配executor、队列input_digest和完整冻结request，再在后台独立物理重放；仅“合法结果”不足以证明它属于这项任务。界面不依赖可编辑展示metadata或任意input_snapshot_file路径。

调度器的failed/cancelled具有终态权威，内层曾经完成的候选仍保留分数，但必须转换成只读失败/取消结果；不能因worker已评分就恢复应用权限。崩溃后从已评分检查点恢复也保留队列失败状态。首次准备失败会打开报告面板显示原因，不静默停在未打开的对话框中。

完整JSON报告复用已有原子film结果写入器：同目录临时文件、完整序列化/flush/fsync，再原子发布。未明确覆盖时拒绝竞争覆盖；写入失败不产生残缺新报告，也不破坏既有报告。测试用部分写后OSError验证新建和覆盖两种情况。
