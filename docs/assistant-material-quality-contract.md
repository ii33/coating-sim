# Assistant optical material quality gate

The assistant calls `validate_assistant_material_quality(profile, *, origin, evidence)` before an assistant-initiated material creation. The module is `coat_sim/core/assistant_material_quality.py`. The material library remains the only persistence owner; its existing schema validation still applies. This gate makes no file or network calls and leaves the input unchanged. A failed `valid` result blocks the assistant operation and returns `errors` to the user; a malformed optical record raises `ValueError` through the existing optical schema validator.

`origin="assistant_reference"` means the assistant is presenting reference data. Each optical set must persist a source URL or DOI, material state or measurement/process conditions, explicit nm/um units, a positive validity interval, and either a complete supported dispersion formula with every required coefficient or a tabulated set whose imported row count equals `evidence[set_id].reference_row_count` from the original cited table. `evidence[set_id].conditions` names the conditions present in the saved notes or process parameter values. Missing evidence is a failure, and interpolation cannot be used to fill a supposedly complete original table. The assistant must report unavailable reference data instead of making coefficients. This structural gate does not independently fetch or authenticate the cited source; `source_verified_externally` is always false.

`origin="user_measurement"` is for an explicit user-supplied measurement table. It permits sparse valid samples without a uniform row threshold and reports `data_character="user_sparse_measurement"`; the caller should retain that label in the saved set notes. Both origins require `evidence[set_id].k_status` as `measured` or `unknown`. Unknown k requires null/absent k data. Measured k requires supplied k values, and an independent formula k table requires its own source. This gate does not equate unknown k with zero.

The material service integration should call the gate before `MaterialLibrary.write` for assistant creation, pass the original profile and evidence through without changing the numerical record, and propagate a failed result as an actionable tool error. The existing user editor and package import paths keep their current schema validation and are not reclassified as assistant reference creation. `update_material` should preserve existing evidence and should use this gate only when the assistant is replacing optical data with new reference claims.
