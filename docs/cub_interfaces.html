算法选择与执行

submit_process_recipe 与兼容入口接受 algorithm=fast/reference/optimize 和严格类型 algorithm_options。Python API 同步验证。fast 默认保留旧设备及 fast_cycle 行为；默认空选项保持原计算身份。reference/optimize 实际使用 CPU，显式 GPU/DirectML 报错。fast_cycle 在这两条路径中不参与执行。

选项范围与适用条件
budget_s三条离线路径均默认不限时；省略或显式 null 表示无时间预算。只在调用者主动指定时使用有限正秒数，0 < 秒 ≤ 300。GUI 的 0 是“不限”显示值，提交时省略 budget_s；API 的数值 0 仍无效。CLI 默认不限，可使用 --budget-s 显式约束基准测试。
max_evaluations整数 1..100；reference 默认自动采样 6、指定采样 4；optimize 默认 9；fast 为旧 API 兼容保留该值但不影响执行，始终只做一次评估，结果给出 execution_option_warnings。
tolerance_percent仅影响 reference，正有限数，默认 0.1%；其他路径兼容接收合法值，明示不参与执行。
rpm_scale_bounds仅影响 optimize，其他路径兼容接收合法值并明示不参与执行；默认 [0.8,1.2]，正且不同端点、包含 1；遵循既有执行模型 |rpm|≤300 限制，并非实机工程上限。
sampling_policy / periodic_integrationreference 默认 automatic / true；可 requested / false。其他路径仅 requested / false。

图：算法和选项随估算身份、冻结输入进入已有独立 CPU 执行路径；不是只在接口增加字段。

摘要含选择；结果 execution_algorithm 和 algorithm_report 报告实际状态、评估次数和验证结果。默认摘要不返完整 trace；通过 read_calculation_result(detail='full') 读取。资产保留完整报告与冻结参数。reference/optimize 不写入 legacy 单次 fast/precise 耗时历史，且耗时估计为未知，预算不当作预测值。路径本身的公式、近似与来源见现有算法文档；本次未改引擎计算公式。
