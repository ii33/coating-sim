# 新波长CPU基线下的异构完整优化闭环（2026-10-17）

本次以新波长CPU路径为基准，完成六种固定分配小扫描、同包装完整256评估优化、五轮交错预热复测，以及三种模式各自独占新进程的五轮持续运行和独立冷启动。未改产品默认或后端代码，未写入校准，未改主仓库/安装器，未推送。

本报告是旧12.2%收益和前次“尚未相对新CPU路径复测”说明的后续闭环；旧比例不再作为新最佳CPU基线下的结论。

## 任务与公平性

60层、400–800nm的10000波长×1角度37°=10000条R目标/候选，s/p平均为非偏振R；候选数另计。目标为CPU参考的各层80nm曲线，优化变量60个厚度，范围30–150nm。使用相同项目deferred batch DE、种子19、种群64、最多3代和256次真实评估，max/RMS排序键及MSE代理目标相同。

CPU单候选采用波长4线程、多候选采用波长8线程，均来自前次扫描。CPU、Intel、异构两侧均通过CoherentBatchEvaluator.evaluate包装。纯CPU/纯Intel总scratch64MiB，异构CPU32MiB+Intel32MiB；OMP/MKL/OpenBLAS为1，没有嵌套候选×波长池。异构只并发独立候选，单候选baseline使用CPU4线程，代际依赖仍串行。

## 完整优化预热复测

每种模式先完成1轮完整256评估优化作为相同预热，首次导入/初始化/精度门禁因此不计入后续稳态。之后每种模式实际完成5轮完整优化，顺序为CPU/XPU/异构、异构/CPU/XPU、XPU/异构/CPU、CPU/异构/XPU、XPU/CPU/异构。没有截断正常推进的任务。

第一组完整复测检测到Explorer最高约1.40个CPU核活动，已完整保留为warm-with-explorer.*，未停止用户应用。负载回落抽样后，用不变模型、分配、线程、种子与重复次数进行一次复测；主表使用这一后续轮，不按速度挑选结果。

## 各模式独占进程的完整优化

交错轮会让CPU基线与已驻留GPU上下文共存，并交替经历GPU负载。为核对纯CPU独占运行的最佳基线，最后固定同一分配补测三种模式各自一个新进程：同样先做1轮完整优化预热，然后连续5轮完整优化；模式间顺序执行。没有新增候选比例或线程配置，不再追加调参/复测。纯CPU进程不初始化torch/XPU，两个GPU模式只初始化其实际需要的一个GPU评估器。此表更接近各自独立持续运行的比较。

|---|---|---:|---:|---:|
| cpu | 2.3749, 2.4014, 2.3847, 2.3807, 2.4643 | 2.384734 | 5.66 | 205.0 |
| xpu | 4.8353, 4.8312, 4.8125, 4.8534, 4.8402 | 4.835277 | 0.99 | 797.1 |
| hybrid | 2.2288, 2.2958, 2.2933, 2.2535, 2.2693 | 2.269259 | 4.43 | 814.7 |

独占进程实测异构相对新CPU最佳路径耗时下降4.84%，吞吐比1.051；纯Intel为CPU耗时的2.028倍。仅能作为当前模型/硬件、重复复用上下文的局部收益，不修改默认，也不声称所有模式都更快。

独占异构阶段还捕获到非本任务python PID11516最高约0.981核；冷XPU阶段python PID33496约1.002核。事后只读身份查询时二者已退出，无法恢复其命令行或断言它们属于哪项任务。因此“未超过1核诊断阈值”不等于完全无背景，不能证明绝对没有并发任务；约4.8%是当前观测值，保留后台噪声和未做频率/功耗归因的限制。没有终止这些进程，也不再追加测量。

## 数值与真实执行

六配置逐点CPU参考比较rtol/atol2e-12通过，最大绝对误差3.3e-14。首组、后续组和冷启动每一轮均实际完成256次评估，failed=0、iteration_limit正常结束；proposal trace SHA256及最优厚度完全相同，best key在2e-12内一致。短预算的最终误差为[0.7845839057285716, 0.47316781262920515]，用于模式一致性而非宣称设计已收敛。

Intel计算每次都断言backend=gpu、runtime=xpu、device名称Intel、output_device=xpu:0，回退则基准失败。每个优化batch的两侧候选数、CPU轴/线程、GPU前向/上传/下载及峰值分配保存在calls元数据。PID匹配的Intel LUID00000000:0000eac0 Compute引擎计数另有原始记录。

## 复跑

在本独立任务目录及既有原生隔离环境，顺序运行launch_hybrid_closure.py scan、launch_hybrid_closure.py warm，和三次cold --mode cpu/xpu/hybrid；run-hybrid-closure.ps1提供顺序编排。最后运行run-hybrid-isolated.ps1进行各模式独占进程复测。启动器设置OMP/MKL/OpenBLAS为1，不安装依赖，不改产品设置。监视器输出*.load.json，所有进程退出码和stdout/stderr保留。
