# 膜系 worker 有限性能剖析（2026-10-12）

固定拓扑缓存的真实 worker 温态收益目前为 1.01–1.13x，尚无稳定降低端到端耗时 20% 的证据。下一步应优先检查完整重放验证中的数据复制与转换，再考虑有界 checkpoint 编码；本机 GPU 仍未验收。

本轮只新增 剖析脚本（历史引用目标，当前公开源码不包含此文件） 和独立报告，没有修改共享生产代码、数值模块、求解器或 UI。复核者 主持，实现者 执行。原始数据见 profile-report.json（历史验证记录，未随公开源码发布），原三次温态基准见 第二阶段证据（历史验证记录，未随公开源码发布）。

后续独立候选阶段已经完成，详见 [第三阶段结果](film-performance-stage3-candidates.md)：复制候选实测变慢而被拒绝；有界编码在当前真实worker仅取得小幅总收益。本文保留原剖析数字与当时建议，不将后续源码/结果追认为原测量。

## 范围、版本与状态

实际主机是 Ryzen 7 4800U、8 核 16 线程、约 16.5 GB RAM、AMD Radeon，已有 PyTorch CPU build。没有用历史 4070 Ti Super/32 GB 硬件信息替代实机核验。

本轮进行一次冷导入、一个原始/缓存 fresh 子进程对照、一条缓存路径 cProfile、各五次同一 checkpoint 的纯内存编码对照。只对自有子进程设置超时；没有停止用户应用、调整优先级、BLAS、驱动、ACL 或队列并发。实际搜索两条路径均为 1001 波长、12 层、seed=19、预算 49，完成 47 次评估、3 代，结果一致。

剖析开始时共享接入补丁未应用，比较原真实 worker 与精确补丁的内存候选；这不是当前生产入口验收。报告保存开始/结束与原温态测量的源码 SHA256。`compute_tasks.py` 已发生其他作者的整文件漂移，不能合并为一个未变源码的速度实验。

本报告收束时只读观察到单作者已新增 `enable_forward_cache` 和 `COAT_SIM_FILM_FORWARD_CACHE == '1'` 显式开关，默认不启用；实际进度和 sidecar 接入也已变化。这些新源码没有使用本报告的数据追认验收，仍须由队列作者复验真实入口。只读观察指纹为 job `ce198c4ac44a0699d7207fff59eb54f3cf20566f92a94361eb0a77e30897d66a`、worker `6f7b69f03305898d174c7898d996d91f1c191b4bb783419b9b0d4d2f1489889f`、compute_tasks `0be851a5c1d2f6d15ab51345f931259fe0183b8d22b160e8c0722709767cf766`；并发工作后续可能继续更新。

## 同一温态运行的耗时分解

每组取总耗时中位数对应的那一次缓存运行，再取该次的各阶段；不能把各阶段独立中位数当作同一运行相加。单位为秒，prepare 已包含在 forward 内。

| 组别 | 总 worker | forward（含 prepare） | prepare 子集 | 完整重放验证 | JSON 写入 | 未分解剩余 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 31 点、4 层、小预算 | 0.4020 | 0.0220 | 0.0043 | 0.0588 | 0.2874 | 0.0338 |
| 1001 点、12 层、小预算 | 1.9973 | 0.0890 | 0.0103 | 0.5898 | 0.8087 | 0.5097 |
| 10001 训练 / 50001 留出、18 层 | 22.0597 | 2.3832 | 0.9419 | 8.6222 | 4.7131 | 6.3411 |
| 1001 点、12 层、实际 47 次搜索评估 | 3.9698 | 0.3725 | 0.0118 | 1.0507 | 1.0983 | 1.4483 |

实际搜索占比为 forward 9.4%、验证 26.5%、JSON 27.7%、剩余 36.5%。大组分别约 10.8%、39.1%、21.4%、28.7%。剩余包含优化控制、评分、对象处理及未单独包围的工作，不能全部归为 Python 循环。

JSON 计时包含实际编码、文件写入与原原子保存路径；本轮没有将磁盘等待与编码精确分离。prepare 计时只覆盖适配器准备，不等于整个作业所有材料冻结/解析工作。原温态实际搜索中位数为原始 4.4793s、缓存 3.9698s，速度比 1.128x；大组首次缓存 25.3596s 对原始 18.0680s，存在约 40% 变慢情形，不能隐藏。

在其他阶段耗时保持不变的假设下，若只把占比 f 的阶段加速 s 倍，总速度比为 `1 / (1 - f + f / s)`。把全部 forward 时间理想化为零，实际搜索也仅约 1.10x、大组约 1.12x。这是由测得分解推导的局部改进上界，不是 GPU 或并行收益测量；改变验证/序列化的完整执行路径后该假设需要重新测量。

## 冷启动、CPU 与机器并发

独立冷导入 child 测得 wall 13.1437s、进程 CPU 12.3281s；其中 SciPy optimize 导入 11.1586s，项目 worker/fixture/候选模块加载 1.9851s。父进程观察的 child 周期为 16.7131s，包含启动、结果落盘和等待，不能将差值全称为进程启动。

fresh 对照的实际 worker-call wall/本进程 CPU 为原始 12.9991s/12.3438s、缓存 10.9111s/10.0625s；`run_worker` 外层 wall 为 13.0008s/10.9124s。这两条 fresh 路径在 worker 中首次惰性导入模块，单次 1.191x 只作诊断，不替换温态三次结果。独立冷导入运行不能直接从其他运行相减。fresh 缓存前向约 0.405s，接近温态 0.373s，也不支持把十秒量级 fresh 总耗时全部归于光学核。

原始/缓存子进程存活期间，全系统 CPU 采样均值约 39.9%/33.0%；冷导入期间约 65.5%，最高约 98%。这些窗口包含导入与作业外工作，且未做排他实机对照，因此能证明环境存在并发负载，不能量化其导致的慢速比例或断言全部波动来自其他程序。wall/CPU 差值也不是排他等待分解。

## Python 热点与编码对照

修正后的 cProfile 只包围实际 worker 调用，不包含 `run_worker` 返回后的 checkpoint 再次检查；首次范围过宽的结果已明确丢弃。修正运行 wall 22.7903s、CPU 21.8594s，包含插桩和首次惰性导入。官方文档明确 profiling 不用于速度基准，因此函数耗时只作定位。[Python 3.12 profiler 文档](https://docs.python.org/3.12/library/profile.html)

函数级统计包括 `deepcopy` 607064 次/独占 1.884s、`asdict_inner` 96264 次/0.215s、`_finite_float` 280280 次/0.401s、`score_condition` 56056 次/0.251s、`weighted_rms_error` 56 次/0.418s。累计时间包含子调用，不能与子函数累计时间重复相加。报告没有保存 caller graph/pstats 文件，尚不能断言复制全部来自优化器、验证或归档中的某一分支；`nt.stat` 5.169s 也只能列为导入/worker 文件操作/housekeeping 未分清的候选。明确的 `open_code`、`create_dynamic` 和 importlib 条目支持存在导入成本，不能解释所有文件操作。

同一个 315977 字节 checkpoint，`json.dump` 到 StringIO 与 `json.dumps` 的文本完全相同，也与既存文件文本相同。五次中位数为 64.415ms 与 13.479ms，差 50.936ms；测试不含文件打开、fsync、原子替换。[Python 3.12 JSON 文档](https://docs.python.org/3.12/library/json.html)

代表运行共七次 JSON 写入，约六次 checkpoint、一次很小的 sidecar。假设六份 checkpoint 均与这份文件同尺寸且取得全部纯编码收益，投影约 0.306s/job，即总耗时 7.7%、原 JSON 阶段 27.8%。这是乐观编码估算，不是持久化路径端到端通过，也不足以单独支持总耗时降低 20%。一次性编码增加瞬时文本内存，不能无界替换通用 `write_json`。

## 两个后续目标

1. **完整重放验证的数据物化与转换。** 先用温态 caller attribution 区分 dataclass/asdict/deepcopy、有限值检查与逐条件稳定 RMS 工作，再在唯一作者范围内复用私有、已校验的中间表示。目标是把同组验证 1.051s 降低至少 20%，约省 0.21s/job；未插桩端到端至少省 0.10s/job 才继续。不得删除检查、改变稳定 `frexp/fsum` 评分、候选顺序、K、seed、预算、精度、全量光谱或错误诊断。所有合法/非法 checkpoint 行为、结果和诊断须保持；这仍是待验证方向。
2. **有界 checkpoint 单次编码。** 只对受控膜系 payload 试验一次编码后写入原原子保存路径，保留字符参数、完整 R/T/A、大小上限、fsync、replace 与取消行为。约 0.306s 是筛选上界，验收要求原始 checkpoint 字节完全相同，并在至少三次未插桩同预算 worker 对照中实际省 ≥0.10s/job，无不可接受峰值 RAM 回退；若未达标就保留原路径。没有建议减少 checkpoint 或验证频次。

以上目标和有限运行次数是**本项目约定**，不宣称已获外部性能验证。当前不扩大并发、不默认打开缓存，也不继续 GPU 优化作为这条 worker 的主要降时手段。CUDA 目标机能力、GPU 完整数值域与真实入口验收仍是剩余边界。
