# 冻结计算输入、工程包与旧版结果文件

更新：2026-10-14。工程迁移使用 `.cproject` 工程包，保存工程清单中当前已保存的受管设计与依赖；草稿、历史对象、计算结果、外部文件和全局材料目录不随包复制。导入创建新工程目录与新工程身份，错误或取消不覆盖已有工程。入口与安全边界见[工程包契约](project-package-contract.md)。本文同时保留 `.coatasset` 旧版设计/计算结果文件的兼容读取说明。两者均不是 Windows 便携运行时 ZIP，也不包含可启动的 Python/Qt 环境；应用 ZIP 的首次启动、目录迁移与失败恢复见[便携版指南](portable-bundle.md)。这些流程不改变沉积或修正板优化物理模型。

## 提交与窗口编辑

- 沉积仿真的不同输入仍可分别提交为独立任务，相同输入重复提交会被阻止。项目模式修正板优化入口位于绑定项目的修正板窗口；单个优化运行期间不接受新的优化提交，须完成或取消后再开始。修正板窗口按其绑定项目的显式已保存默认配置解析工艺、机器及完整依赖闭包，不从可见工艺窗口、最近打开记录或全局资源库推断输入；缺少默认配置或依赖、默认闭包存在 dirty/pending 草稿、配置过期等情况均阻止提交。优化开始时再次解析并冻结项目、配置、工艺和修订身份，以及该优化支持的配置设置；评分器仍遵循既有映射边界，主沉积 algorithm 与 algorithm_options 不传给修正板优化
- 沉积仿真提交重新读取文件内容，通过类型校验后捕获工艺、机器、源、基片和修正板。依赖清单带规范 JSON SHA-256；计算、结果摘要和后续导出均来自该次捕获，之后修改同名文件不会改变已排队任务
- GUI 在内存中捕获依赖；MCP 为运行审计保存单个包含 typed JSON 的 manifest，而不为工艺/优化任务再生成机器、基片等伪用户文件
- 结果与当前草稿是不同状态。窗口展示最近一次提交的结果；较早的任务仍在队列独立完成。隐藏或关闭窗口不会取消已接受的调度任务；项目关闭时冻结新的优化提交与结果保存。项目会话最终 dispose 时只 detach/reap 结果观察器，不取消已提交任务；用户显式取消修正板优化时才请求取消该优化作业

## 修正板优化

沿用已载入轮廓优化、从零设计、固定板＋可变板三类模式。固定板几何和孔洞不会被优化改写。结果先是新的 pending mask design，不覆盖原机器或板文件。选择候选并命名后点“保存到当前项目”，会在绑定项目中创建新的受管修正板资源；不会覆盖原板。打开优化产物工艺时，会将完整依赖闭包导入同一项目并打开新工艺草稿，不更改项目默认配置。

低层兼容调用仍可显式传 pending_only=False 生成旧式独立副本；GUI、MCP 和 API 默认均使用待保存设计。优化报告及计算结果保存在该次临时结果目录，真正的 JSON 设计只有用户主动保存/导出才生成。

## .coatasset 旧版兼容

兼容读取原 .coatasset 格式，版本 2 向前兼容读取版本 1。计算完成仍可生成临时 result.coatasset，仿真和队列的旧版结果文件入口保留命名保存与读取能力。文件可不包含计算数组和图像，但仍保留参数、工艺和完整设计依赖；它不是工程包，不能替代完整工程迁移。

- manifest 为成员标记类型/角色、相对路径、长度和 SHA-256
- 包内设计引用改写为相对路径，移到另一台机器仍能解析
- 不嵌入任意路径文件、凭据或可执行代码，不自动执行包内容；拒绝 ZIP 路径穿越、符号链接、名称冲突、散列不符与对象数组
- 读取有文件数/展开容量/数组头限制；旧包没有冻结依赖时会明确缺少 portable inputs，不能伪称可移植

## 设计器与仿真器

源、基片、修正板、机器和工艺普通设计窗口不再显示旧版包浏览弹窗。新工程与工程包的导入导出由工程启动器负责，资源操作栏仍提供明确的外部资源副本导入及当前资源连同依赖导出。

旧 `.coatasset` 数据仍可通过 `CoatService.read_simulation_asset` / `export_simulation_asset` 或保留的兼容 `AssetBrowserBridge` 读取并导出；类型校验、完整相对路径、依赖闭包和覆盖确认继续生效。含规范 `.csrc/.csub/.cmsk/.cmac/.cproc` 资源的导出结果可从相应设计器的普通打开入口读取，进入工程时由项目资源导入入口复制为受管资源。历史容器内的 `.json` 和长扩展名仍由内部成员 reader 读取；这些成员名不会因此变成可直接打开的独立设计文件，普通设计文件仍遵守现有规范短扩展名契约。底层兼容 reader/exporter 拥有数据与错误状态，普通设计器拥有自己的草稿、保存及关闭确认；去掉弹窗不会创建全局可变状态或改写旧文件。仿真器的旧版结果文件入口仍可显示已有结果，读取不含结果的文件仍可使用其冻结参数重新提交。

## 验证边界

回归覆盖：同一窗口两任务、提交后改同名文件、不同摘要散列、真实小规模优化待保存结果、固定板保留、六个 Qt 窗口加载且普通设计器无旧包弹窗、明确兼容 reader 的全部设计类型导出后重开、可选结果、覆盖取消/确认、依赖往返及恶意包拒绝；工程包另有受管内容、安全校验与新身份往返测试。Qt 截图为真实离屏渲染；不代表 Windows GPU 内存峰值或 5 GB OOM 问题已经根治。
