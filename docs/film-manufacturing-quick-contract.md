# 工艺薄层修复 Qt Quick 边界（更新2026-10-30）

自动薄层修复现作为膜系优化算法页的 `automatic_repair` 选项，与普通优化及减层/减厚共享同一算法选择、参数页、开始/取消/显式应用工具栏；不再从第二个优化按钮打开独立对话框。算法页由 `FilmOptimizationQuickController.searchMode` 独占算法选择；`FilmManufacturingQuickController` 仍是唯一薄层参数、实时证据、取消和候选所有者，并复用原 `film_manufacturing_repair` 本地 CPU worker 与来源会话安全应用契约。

此优化入口只暴露最后确认的两个制造参数：单层物理厚度下限（nm）和相对本轮原曲线逐点最大绝对变化（百分点）。内部旧请求使用 `reference_nm=下限` 且 `thickness_tolerance_nm=0` 编码同一个物理下限；此兼容字段不是额外用户参数，不得恢复为总厚目标或宽松容差。自动识别薄层，不手选优化层，不显示旧的每路线预算。所有原目标保护、材料闭包、训练/独立审计、取消与应用边界沿用[自动修复物理契约](film-automatic-repair-contract.md)。

算法页参数与反馈区在运行中显示当前 worker 阶段、检测层、原/当前/最佳物理总厚、训练/独立审计最大误差和相对源曲线的已核验最大变化，以及逐层差异背景条。它只读取现有核验快照，不增加物理调用；隐藏或切换该页不会暂停计算。相应 UI 数据所有权、显示故障和 latest-only I/O 见[减量实时反馈契约](film-reduction-contract.md#逐轮实时反馈仅显示不改变算法)。

唯一UI状态所有者为 `FilmManufacturingQuickController`，QML转发真实编辑、取消及确认事件。三个初始草稿为空；非法输入保留原文，不自动夹紧。下限F=max(0,目标−厚度容差)只针对非零保留层，较厚层无目标+容差上界；精确0是合法消层分支，不新增第四个用户参数。当前v3把全部厚度修好作为完成条件而非中途应用门槛，较小但严格改善的厚度不足也可应用。物理有效性、原生约束、相对固定原快照的逐点光学容差及原指标保护始终有效。材料插值/外推、QW到物理nm的换算及引擎支持域沿用既有实现，不新增材料范围限制。

控制器以 `FilmOptimizationRunCoordinator` 管理代次与取消。后台QRunnable提前冻结来源、三项参数、材料内容、可编辑材料闭包、原目标和比较设置，经既有 `film_manufacturing_repair` 本地CPU executor执行v3作业；v1/v2历史和程序请求仍走各自原路径。普通进度只广播有界标量，worker原子保存固定job-local实时快照；client按job/input digest及序号只读获取。Qt主线程只做绑定/结构证据校验，取消和进度接收均不追加光学重算。提交结果未知时保留同一job ID，取消意图不冒充服务终态。

表格同时显示原始、当前试探、最佳完整候选的单层厚度和变化；按稳定layer ID与来源ID配对，新增、删除、合并明确标记，不按行号错配。当前精确0标为“待核验消层”，原始试探仍仅预览；删除0、同材料同optical_set合并后重新训练并独审的新hash才可成为冠军，不能用旧评分或求解收敛标记替代。零厚定向片可让选中变量在训练中穿过原生最小非零厚度；这样的中间点仍不可应用，正式候选全部非零层及合并后层必须守原生工艺界。原目标训练/审计、逐点最大曲线差、厚度不足、是否全部满足及实际工作账目分开显示。无启用原目标时原指标为不适用，仍检查按当前仿真/原曲线设置确定的逐点变化；仅缺少已有设置时复用既有仿真默认值。未完全修好或原指标仍违规必须如实显示，不用均值抵消峰违规。

`liveTotals` 与逐层表使用同一current/best快照投影，分别给出candidate hash、单调seq、物理nm总厚和显示模式；QW未换算时为未知，真实空设计才是0。各行仅以一条背景条表示当前厚度，共用 `liveBarScaleNm`；刻度上限由本轮原始、当前和最佳厚度共同确定，只扩不缩，下轮重置；删除显示来源行零长度条，合并按真实origins显示，不混用旧帧总量。应用成功后主显示使用实际完整best的层、hash和总厚，旧未审current不再冒充已应用结果。

“应用当前改进”确认时冻结所见候选hash并停止本轮，后续更好候选不替换用户已确认的对象。“取消优化”终止计算，取得终态后自动应用最后完整核验的改善冠军一次；不补算物理，不采用未审计试探。没有有效改善或来源已失效则不写回。自然结束后仍可回看或手动应用，不因任意终态自动写入。

owner的 `_manufacturing_can_apply(payload, context, snapshot)` 和 `_apply_manufacturing_candidate(payload, context, snapshot)` 是最终应用边界，复用 `applySynthesizedDesign`、冻结可编辑材料闭包及一次撤销事务。应用完整拓扑并刷新层表、约束及光谱。实际主优化器未应用提案仍有优先权，已应用的旧主结果不遮住后来修复光谱。context绑定来源session/controller、revision、pendingEditEpoch、目标签名、项目根/代次及操作；来源编辑、材料/目标/比较设置变化、项目切换、关闭/解绑或shutdown导致的失效取消不等同用户取消，禁止自动覆盖。应用前消费一次性job/hash标记，自己的写回信号、迟到帧及重复终态不能重复写回。普通优化、敏感性与本操作互斥。

敏感性表格草稿仍存于已有 `workflow_settings.optimization.sensitivity_table`。owner延迟创建时调用 `loadTableConfiguration()`，通过 `exportTableConfiguration()`导出，订阅无参 `tableConfigurationEdited()` 后复用 `_persist_configuration()`；加载不触发编辑持久化。未打开该页也保留已有草稿。只有该非物理字段不使制造任务失效；实际应用修复时从仍有效当前来源保留其最新值，不能用任务早期冻结草稿回滚用户表格。几何、光学目标、仿真和材料仍走完整来源保护。

owner与表格loader共用同一个严格纯解析器，保留原schema、空配置和未完成文本草稿语义。导入先完成全部外层及嵌套校验，再尊重真实表格控制器的忙/关闭拒绝；成功后才提交owner、表格及缓存，不能吞掉loader的False。坏schema、重复层ID、非法外层配置或忙中拒绝均返回失败并保留原表、未打开页缓存、持久配置和原结果；不通过临时新控制器绕过忙状态。

运行失败保留输入及已完成比较；关闭运行任务需走现有确认，但关闭不代表应用意图。历史报告使用独立只读AppWindow，无来源上下文和应用资格；复用共享 `prepare_window_geometry` 的 `film_manufacturing_report`，默认1100×760逻辑尺寸及屏幕夹取/恢复，无几何例外。offscreen QTest不是原生多屏/DPI人工验收，实际验证范围以交付manifest为准。

旧v1配额仍按十进制原文精确转换，旧v2保留有限预算及完整成功应用语义，不以v3重标历史。当前v3无固定总秒数、总提案或总物理调用cap；局部求解片有界，取消及资源准入有效，轨迹有界保留。自然局部停止或本轮未找到不能宣称全局无解。
