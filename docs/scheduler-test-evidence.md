# Scheduler lifecycle regression evidence

历史开发记录：本页的运行数字与环境仅说明当时的限定验证，不代表当前公开提交通过 CI；原始私有执行记录未随公开源码发布。

This file records the reproducible integration checks for the process-independent
compute scheduler. The suite uses the local `probe` executor only; it does not
launch the deposition simulator, DirectML, or GPU work.

## Scope and execution

Run from the independent `scheduler-workspace` checkout with its project
interpreter:

```powershell
C:\a\wk\coat\deposition_sim\.conda\python.exe -m unittest discover -s tests -p test_scheduler_service.py -v
```

Each test provisions a fresh `tempfile.TemporaryDirectory` scheduler root and
explicitly calls `stop()` during cleanup. Temporary directories set
`ignore_cleanup_errors=True` because Windows indexing and SQLite handles can
briefly delay file release. The suite does not change the source project's
runtime database or run its service as a Windows service.

## Contract exercised

The client accepts a JSON-compatible version 1 `JobSpec` dictionary and submits
only the registered `probe` executor. Tests expect `queued`, `running`,
`succeeded`, `failed`, and `cancelled` lifecycle states. Duplicate submission
with the same ID and same spec is idempotent; reusing that ID with different
parameters is a conflict. Result payloads are file assets: status and result
responses expose artifact references and payload metadata rather than embedding
the generated bytes.

Cancellation is tracked as the durable `cancel_requested` flag while the job
may remain in `running`; terminal stability is checked after the worker settles.
The API does not need a separate transient `cancelling` state.

Expected failure labels are `worker_crashed` for an abruptly exiting worker,
`result_save_failed` when result persistence fails, and
`scheduler_interrupted` plus `interrupted: true` for work that was running
when the daemon stopped. Queued work remains eligible after restart. A client
process exiting on its own must leave submitted work under daemon ownership.

| Regression | Test | Evidence recorded by assertions |
| --- | --- | --- |
| Submitting process exits while work continues | `test_submitting_client_process_exit_does_not_cancel_job` | Child client process exits; observer sees success |

| Restart resumes queued work and records interruption | `test_restart_resumes_queued_jobs_and_marks_running_job_interrupted` | Running task has explicit interruption evidence; queued task succeeds |

## Run record

The project environment has no `pytest` package, so the module exposes its
functional checks through standard-library `unittest` discovery. The exact
command above runs the same test functions without installing dependencies.

### Results

- Interpreter: Python 3.12.14 at
  `C:\a\wk\coat\deposition_sim\.conda\python.exe`.
- Command: `python.exe -m unittest discover -s tests -p test_scheduler_service.py -v`.
- Result: 14 tests passed in 54.649 seconds.
- Covered: client-process exit, shared-client status/result/cancel, same-ID
  deduplication/conflict, twelve-job enqueue sequence, restart recovery and
  interruption, distinct crash/save errors, cancellation races including a
  near-completion duplicate request with one cancel event and one terminal event,
  database rollback with no `.cancel` marker, 8 MiB artifact
  transfer with SHA-256 verification, frozen-input digest, event reconnect and
  reset snapshot, and memory-only hot queries.
- An earlier attempt to run pytest could not start because pytest is absent.
  One interim lifecycle run also used an incorrect Windows PID probe based on
  `os.kill(pid, 0)`; its two stop assertions are invalid and were excluded. The
  helper now uses the project's safe process-identity check and creation stamp;
  the final 14-test run above passed with that check.
- GPU / DirectML validation: intentionally not run by this suite.
- Hot status, snapshot, and event queries are instrumented by making persistent
  store reads raise; no file-lock or indexer interference simulates disk failure.
- Windows environment notes: SQLite/indexer lock timing is handled with
  isolated temporary roots and best-effort cleanup. Symlink behavior is not
  exercised by these lifecycle tests.
