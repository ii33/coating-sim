# Intel 核显支持范围

更新：2026-10-17。设备出现、运行时探测通过、有限数值验证和完整任务验收是不同状态。设备弹窗按任务显示支持范围；运行时缺失或检查失败时仍显示不可用原因，不会用 CPU 结果声称 GPU 通过。

| 功能 | 当前支持口径 | 限制与操作 |
| --- | --- | --- |
| CPU 沉积、膜系优化、外观 | 产品已支持 | 作为可明确选择的本机路径；不表示所有物理模型或输入已全面标定。 |
| Intel 核显 DirectML 平面沉积 | 数值后端有限验证通过 | Windows、兼容 torch-directml 环境、显式 Intel 设备绑定的两个限定测试之一；不是当前默认设备选择的端到端验收。 |
| DirectML 遮板/姿态边界 | 实验范围，边界精度待验证 | 已观察到遮挡采样差异。涉及边界的结果应与 CPU FP64 对照，不能宣称完整精度已通过。 |
| Intel XPU 膜系前向批评估 | 实验路径，尚未通过任务验收 | FP64/complex128 基础探测通过，但实际项目批评估两次超时；桌面膜系优化仍使用 CPU，不因 XPU 枚举成功启用 GPU。 |
| Intel 核显外观 GPU | 不可用：产品后端未实现 | 现有 GPU 外观入口只接受 NVIDIA CUDA/OptiX；Intel 没有 DirectML、XPU、SYCL 或 DXR 渲染入口。可显式选择 CPU 外观。 |

## 已有实测依据

原生 Windows 主机 sakuya，Intel Core Ultra 7 265K / Intel(R) Graphics，PCI `8086:7D67`，驱动 `32.0.101.9033`，D3D12 FL 12_2。源码基线为 `3ff4916611e7f3f1bb71ac32d435051f203aa224`。本说明归纳该基线的实测记录，不声称后续整个版本重新完成硬件验收，也不能推广为所有 Intel 核显和驱动的保证。

沉积测试使用独立 Python 3.12.14、torch-directml `0.2.5.dev240914` / PyTorch 2.4.1 / NumPy 1.26.4。生产数学路径未修改，测试进程显式绑定 DirectML 索引 1，GPU 张量和读回均核验为 `privateuseone:1`，计算为 FP32；CPU 对照为 FP64。最终 NumPy float64 容器不会恢复 GPU FP32 已损失的精度。

- 平面点源：257×257 网格、51,433 有效点、600 步，最大归一化绝对误差 `6.31723e-7`，筛查超阈值点为 0。
- 倾斜/遮板/衰减：181×181 网格、25,445 有效点、360 步，7 点超筛查阈值，最大归一化绝对误差 `0.00352624`、最大相对误差约 `0.364455%`。单点重放观察到遮板投影跨越边界，不能归结为所有 FP32 都必然出现同样偏差。
- 使用的 `rtol=1e-4, atol=1e-5` 是此次测试的项目筛查约定，不是产品精度承诺。未扩大容差，也未修改几何或计算算法。

XPU 测试使用官方 PyTorch `2.10.0+xpu`。FP32、FP64、complex128 及项目 `gpu_capability("xpu")` 基础检查通过；16 候选×81 波长×2 内层膜的真实批评估先后达到 90 秒和 180 秒诊断期限，没有返回批量结果、实际评估后端或 CPU 回落元数据。因此不能报告膜系 GPU 任务通过，也不能将其描述成硬件没有 FP64 或只是缺依赖。

CPU 外观在真实 `render_job()` 中完成 2 波长×24×24 像素、2 spp 的限定运行，执行元数据为 `cpu_scalar`。这不是 Intel GPU 渲染证据，也不是外观物理精度认证。

完整原始报告及数据在本次本机验收目录 `task-2/INTEL-GPU-TEST-REPORT.md`、`results-summary.json`；它们未随仓库发布。公开仓库中的本页保留设备、版本、输入规模、结果及验证限制，不嵌入用户安装目录或运行时凭据。

## 当前设备选择和回退

正式沉积选择器仍保留 CPU、CUDA、DirectML 的手动选择。`directml:default` 只表示现有后端的默认/AMD 优先选择，不是 Intel 物理适配器 ID；多 GPU 主机不能仅凭选择 DirectML 就认定计算发生在 Intel 上。设备名称未知时保持“默认设备／物理 GPU ID 未指定”，不伪造 Intel 标签。此轮只补支持标注，没有增加物理适配器绑定协议。

运行探测的 `available` 只表示该后端的有限初始化和算术探测成功；`runtime_probe` 与 `support_level`、`support_note` 分别表达运行状态和验收范围，不将硬件名称升级为任务支持。选择后限制说明继续可见。缺少依赖、探测超时或失败仍保留明确原因；不可用设备不接受选择。

显式 GPU 选择不静默替换为 CPU 或其他主机，参考/转速搜索等仅 CPU 算法仍拒绝 GPU。自动后端模式若沿用既有回退，会记录实际 `backend_selected` 与回落说明；验收必须核对实际后端。CPU 是用户可明确选择的路径，不能替代 Intel GPU 支持证据。

界面只新增只读范围说明，唯一状态所有者仍为 `ComputeTarget`；队列拥有作业状态、结果与取消。探测继续在有期限的后台进程中执行，过期异步结果按原 generation 丢弃。没有新增计算、安装依赖、修改驱动或改变取消语义。
