# 目标进展交接与工艺薄层修复 GUI 契约

日期：2026-10-25。基于既有 v5 冻结请求与显式选层制造修复 API。两项均为实验功能，不承诺优化效率、收敛或制造性能；不改变原目标、光谱网格、nominal 验收或既有 current/best 绘图、动画、硬件加速设置。

## 目标进展交接

既有优化窗口“算法 / 从零合成”内提供默认关闭的开关与四个空白输入。`FilmOptimizationQuickController` 唯一拥有开关、原文草稿、提交错误及合法策略；纯适配器 `film_objective_progress_editor.py` 只解析，不填阈值。每窗口已接受步数和连续停滞窗口数为可精确表示的正十进制整数；两个相对进展下限为有限非负、无量纲比例，0.001 表示 0.1%，不是光谱百分点或目标余量。

编辑时保留原文；Enter/失焦校验四项，不重置、夹取或运行旧值。开启但任一项无效时禁止开始、冻结与配置导出；关闭时保留输入但冻结策略为 null。Editor 配置可保存开关与四项原文，旧配置从明确的 policy 或 null 恢复；若二者矛盾则原子拒绝。任务仍使用 `objective_progress_policy` 的原有 v5 字段，未启用不构造策略，不生成默认阈值。该策略仅支持 hybrid；legacy 不静默忽略已开启策略。

## 工艺薄层修复

现有优化窗口工具栏打开同窗口内的主题对话框，不增加窗口几何例外。独立 `FilmManufacturingQuickController` 唯一拥有其选层、reference_nm、各路线预算、进度与结果；来源编辑器仍唯一拥有实际设计、材料 provider、revision 和一步撤销。用户明确勾选真实前表面层 ID，并填写正 reference_nm、每路评价/迭代/时间上限；不按薄层阈值自动选择，不把参考厚度解释成全局硬制造下限，不预置 25 nm 或特定层数。

来源设计、原目标、容限、独立审计倍率、真实材料内容以及项目/会话/编辑版本在提交时冻结。完整来源训练与独立审计，以及 A 保留增厚 / B 删除合并均在现有本地 CPU scheduler 后台执行；UI 不执行物理求值，远端与 GPU 不自动启用。worker 通过已有取消传输、完整调用准入与资源策略，保留完成的证据并明确区分取消、预算、资源和错误。异步结果以作业和 operation 身份关联，旧 attempt、关闭、detach 或来源失效不得回写。

原设计、A 与 B 并列显示层数、最小物理厚度、总厚度 D、每个原波段的均值与最坏违规、完整训练/独立审计状态和调用账本。没有完整独立审计只能为未知/未通过，不能从空错误列表、max_error=0 或求解容差推断通过。修复候选与原光谱冠军是不同角色，不宣称每个指标同时占优。

只有用户显式选中完整审计路线并点击应用，才尝试原子应用；完成、取消和关闭均不自动应用。应用前重核原会话、来源 revision、pendingEditEpoch、原目标、冻结材料/物理指纹和项目 generation；发生变化保留报告且拒绝覆盖。来源编辑器使用现有冻结完整可编辑材料闭包及应用/撤销规则；成功形成一次可撤销、未保存修改，不自动保存项目。报告另存须包含完整冻结请求与原始证据，不只保存界面汇总。

## 验证范围

本轮使用助手自有 Linux 主机、既有 PySide6 6.12.0 离屏窗口和 Qt 真实键鼠事件。定向测试包括默认关闭、四项非法/有效原文、Enter/Tab/关闭守卫、配置导入导出与 v5 冻结往返，以及制造任务生命周期、取消、来源改变、选择应用、失败和报告。并不构成 Windows 原生、用户设备、GPU 或生产工艺验证；实际通过项与未执行项以本轮测试报告为准。
